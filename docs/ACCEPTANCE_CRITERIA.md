# 驗收條件

> **依據**：規劃書原文 [plan/PLAN_V2.2.2.md](plan/PLAN_V2.2.2.md) 第八節（Spike 0 通過條件）與第十節（最小驗收案例），
> 以及使用者 2026-11-11 於對話中核准的條件。兩者不一致處見 [PLAN_GAPS.md](PLAN_GAPS.md) 第三節。
> 目前狀態見 [TEST_STATUS.md](TEST_STATUS.md)，測試步驟見 [TESTING.md](TESTING.md)。

## 1. Spike 0 Gate（G0）

**G0-01～05 均為必要驗收，且每項都在兩台實體 Windows 11 上實測。** G0-06、G0-07 不阻擋 MVP。

以下「必須驗證」欄為規劃書原文；「對話補充」為 2026-11-11 核准表格中的額外文字。

| Gate | 必須驗證（規劃書） | 對話補充 | 等級 | 失敗處理 |
| --- | --- | --- | --- | --- |
| G0-01 | 兩台 Win11 直接 IP、TLS 1.3、SHA-256(SPKI) 指紋核對、自訂帳密登入、三條連線與一次性 Token；**Video、File 中斷後可獨立重連，Control 中斷則撤銷工作階段** | 首次 SPKI 指紋核對 | 必要 | 阻擋 M1 |
| G0-02 | DXGI → H.264 → 控制端顯示、鍵鼠可操作 | 能實際操作鍵盤與滑鼠 | 必要 | 阻擋 M1 |
| G0-03 | ① Host.exe 於登入時以使用者權限自動啟動。② 安全暫停與恢復：鎖定、UAC 或擷取中斷時停止輸入、畫面與剪貼簿，不把舊畫面當即時畫面，桌面恢復正常後才重新接受控制，且丟棄暫停前未處理的鍵鼠。③ 登出時中止連線。④ Windows 使用者 A → B → A：舊 Host 讓出 52100，新 Host 不繼承任何授權。⑤ 斷線、Video 中斷、輸入逾時時釋放按鍵；HostGuard 的 GUARD-01～05 實機通過 | 安全桌面不可操作時暫停，恢復時丟棄舊輸入事件 | 必要 | 阻擋 M1 |
| G0-04 | HwndHost 畫面區收得到鍵鼠，且能從本地 Explorer 拖入檔案與資料夾 | 若失敗，驗證替代渲染方案 | 必要 | 改用 D3DImage 或獨立視窗，以延遲與事件可靠度實測定案 |
| G0-05 | 遠端面板的檔案與資料夾能拖到本地 Explorer；雜湊不符或中斷時目標不留殘缺檔；暫存備援可運作 | 雜湊錯誤、中斷及取消有正確處理 | 必要 | 串流不符完整性 → 以暫存方案為預設；兩者皆不通過 → 阻擋 M3 |
| G0-06 | 找出符合 Windows 安全模型的方式操作管理員 PowerShell（候選：UIAccess），不提升權限、不降低安全設定 | 可行性研究 | 不阻擋 | MVP 維持「偵測並提示」；正式版另行規劃 |
| G0-07 | 嘗試辨識 UAC 提示並顯示專用訊息；無法可靠辨識時使用通用訊息，不得把所有 DXGI 擷取失敗判為 UAC | 安全暫停與恢復屬 G0-03 必要條件 | 不阻擋 | 一律顯示「遠端桌面暫時無法操作」 |

Spike 0 同時須確認：.NET 能否取得 TLS exporter（Session Token 綁定用），以及軟體 H.264 編碼器的授權與專利責任。

## 2. HostGuard（GUARD）

規劃書與對話核准的 GUARD 定義不同（[PLAN_GAPS.md](PLAN_GAPS.md) G-18），**待使用者決定採用哪一版或合併**。在決定前兩版並列，實作與測試以兩版聯集為準。

### 2.1 規劃書第十節

| ID | 驗證項目 | 通過標準 |
| --- | --- | --- |
| GUARD-01 | Host.exe 崩潰前後的按鍵狀態：遠端按住 Shift、Ctrl 與滑鼠左鍵時，分別以強制結束、未處理例外、Host 無回應三種方式中斷 | 記錄崩潰前後各鍵狀態與時間戳；3 秒內全部放開；重啟後須重新登入；三種方式各附記錄檔與錄影 |
| GUARD-02 | 不影響本機使用者 | 遠端控制中、Host 崩潰與恢復期間，本機實體鍵鼠皆可正常操作；HostGuard 只放開狀態表中的鍵，本機按住的其他鍵不被放開；經 IPC 增加的輸入延遲 p95 < 5 ms（暫定） |
| GUARD-03 | 重啟政策 | 正常結束（系統列結束、登出）不重啟；異常結束依退避重啟；10 分鐘內第 6 次不再重啟並寫入事件記錄 |
| GUARD-04 | 本機 IPC 安全 | 非 HostGuard 啟動的程序、其他使用者或其他工作階段連線被拒；白名單外訊息與舊世代事件被丟棄並記錄 |
| GUARD-05 | 不可控制狀態與 HostGuard 故障 | 鎖定、UAC、登出、切換使用者時，即使收到事件也不注入並記錄丟棄；結束 HostGuard 時，Host.exe 立即停止遠端控制並提示，並記錄是否有殘留按鍵（已知限制） |

### 2.2 對話核准版（2026-11-11）

| ID | 驗證內容 |
| --- | --- |
| GUARD-01 | 遠端按住 Ctrl 時強制終止 Host.exe，Guard 偵測結束並嘗試釋放輸入 |
| GUARD-02 | 遠端按住滑鼠左鍵拖曳時強制終止 Host.exe，清理滑鼠按住狀態 |
| GUARD-03 | Host.exe 連續崩潰，確認不會無限重啟 |
| GUARD-04 | 本機與遠端使用者同時操作修飾鍵時發生崩潰，確認是否誤干擾本機輸入，並記錄 Windows API 限制 |
| GUARD-05 | 鎖定、登出、切換使用者、正常結束工具時，不得持續注入輸入或重啟錯誤工作階段 |

HostGuard 維持同一使用者權限、不連網路的獨立小型元件。

## 3. MVP 最小驗收案例（規劃書第十節）

以下 24 項全部通過才算 MVP 完成（GUARD-01～05 見第 2 節，合計 24 項）。延遲一律以 p95 評估。
測試設備建議至少一台內顯筆電與一台獨顯桌機，驗收報告寫明型號、Windows 版本與網路條件。

| ID | 驗證項目 | 通過標準 |
| --- | --- | --- |
| NET-01 | 同區網 IP 連線 | 不需外部服務；關閉外網仍可連線 |
| NET-02 | 無法路由的 IP / CGNAT | 明確提示不可達，不誤報為驗證失敗 |
| NET-03 | 分別中斷 Video、File、Control 連線 | Video、File 獨立重連且遠端桌面不關閉，File 從已驗證資料塊續傳；Control 中斷則撤銷整個工作階段 |
| SEC-01 | 首次指紋核對 | 兩端顯示相同的 SHA-256(SPKI)，可由被控端獨立核對，未確認不可繼續 |
| SEC-02 | 主機憑證變更 | 直接拒絕，需人工重新核准 |
| SEC-03 | 錯誤密碼、爆破、超大封包、Token 重放 | 節流、拒絕、可稽核、不當機 |
| SESS-01 | 登入、斷線、本地中斷、Host.exe 崩潰 | 授權即時撤銷、按鍵釋放；Host.exe 崩潰時依 GUARD-01 |
| SESS-02 | 鎖定、本機解鎖、登出、Windows 使用者 A → B → A 切換 | 行為符合工作階段狀態表，不誤連其他使用者桌面；舊 Host 讓出 52100，新 Host 不繼承授權 |
| VID-01 | 1080p 畫面與游標 | 無嚴重黑屏、無長期積壓與不同步 |
| VID-02 | UAC 提示、Win+L、解析度切換 | 暫停期間不送輸入與剪貼簿、不把舊畫面當即時畫面；恢復後丟棄舊輸入；無法可靠辨識 UAC 時顯示通用訊息 |
| HID-01 | 注音、英文、Alt+Tab、高 DPI | 正確輸入與定位 |
| HID-02 | 前景為管理員 PowerShell | MVP：明確提示無法操作；採用候選方案後：可打字與點擊 |
| CLP-01 | 雙向中英文剪貼簿 | 不迴圈、不重複、斷線停止同步 |
| FILE-01 | 1 GB 大檔雙向 | 雜湊一致，取消與錯誤有明確結果 |
| FILE-02 | 千個小檔與巢狀資料夾雙向 | 路徑與結構保留、無路徑穿越、同名行為符合預期 |
| FILE-03 | 本地 Explorer 拖入、遠端面板拖出（檔案與資料夾） | 目標真的建立正確的檔案與資料夾結構 |
| FILE-04 | 拖出過程中斷線或雜湊不符 | 本地目標不留殘缺檔，並顯示失敗原因 |
| PERF-01 | 傳 1 GB 檔時操作鍵鼠 | 區網、指定測試機下，鍵鼠 p95 輸入到畫面延遲 < 100 ms（暫定門檻） |
| INST-01 | 安裝、升級、移除 | 排程工作與防火牆正確；升級保留主機金鑰與帳號；移除時詢問是否刪除使用者資料 |

## 4. 狀態定義（對話核准，2026-11-11）

| 狀態 | 意義 |
| --- | --- |
| NOT_STARTED | 尚未開始開發或測試 |
| IN_PROGRESS | 開發中，尚未進入驗收 |
| PARTIAL_PASS | 部分條件已驗證通過，其餘尚未執行（須註明缺哪些） |
| PASS | 全部條件已在規定環境下驗證通過，並附第 5 節證據 |
| FAIL | 驗證未通過（保留紀錄，修正後重新驗證） |
| BLOCKED | 因外部因素無法進行（須註明原因） |

規劃書原文只允許 PASS、FAIL、未測；目前採上表（較新），「未測」對應 NOT_STARTED / IN_PROGRESS（[PLAN_GAPS.md](PLAN_GAPS.md) G-19）。

## 5. 驗收規則與證據

1. **未執行的雙機測試不得以單機結果代替。** Spike 0 每個 Gate 都要在兩台實體 Windows 11 上實測。
2. **PASS 須附**（規劃書第八節）：測試步驟、測試機型號與 Windows 版本、記錄檔、**螢幕錄影**。
3. **FAIL 須保留**失敗證據與重現步驟。不刪除失敗測試紀錄，修正後新增一筆 PASS。
4. 自動測試（含 Linux 上的跨平台測試）只能作為佐證，不能取代 Windows 實機驗收。
5. 每個開發階段完成後執行相關回歸測試，結果記入測試紀錄。
6. 每筆紀錄需註明：日期、commit、環境（實機 / 雲端）、執行者、結果、證據位置。
