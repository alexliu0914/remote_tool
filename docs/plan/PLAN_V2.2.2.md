## 一、目標與範圍

結論：自建 Windows 11 x64 ↔ Windows 11 x64 點對點遠端桌面。控制端直接以 IP 連到被控端，不經中央協調、雲端或中繼伺服器；被控端只在 Windows 已登入、一般桌面可操作時提供控制。開發估算 12–17 週（含 Spike 0）。

### MVP 功能邊界

| 類別 | MVP 做 | 不做 |
| --- | --- | --- |
| 連線與認證 | 直接 IP、TLS 1.3、自訂帳號密碼、首次手動核對主機指紋、三條連線、同時一名控制者 | Windows 帳密登入、中繼、協調伺服器 |
| 工作階段 | 被控端已登入時可控制；鎖定時暫停、本機解鎖後恢復；登出時中止連線 | 登入前連線、控制登入或鎖定畫面、遠端解鎖 |
| 畫面與輸入 | 1080p 30 fps 目標、鍵鼠、中英文輸入與「貼上 Unicode 文字」、多螢幕 | UAC 安全桌面操作、遠端提升權限、Ctrl+Alt+Del |
| 管理員視窗 | 不保證可操作（Windows UIPI 會擋下一般權限送出的輸入）；偵測到時提示使用者 | 為此降低 Windows 安全設定 |
| 剪貼簿 | 雙向文字 | 圖片、檔案剪貼簿 |
| 檔案 | 本地 Explorer → 遠端工具、遠端檔案面板 → 本地 Explorer，皆支援檔案與資料夾；限速、完整性驗證、進度、取消 | 遠端 Explorer 直接拖到本地 Explorer、刪除來源（只複製） |
| 其他 | 被操控提示、稽核記錄 | 手機、Mac、聊天、音訊、錄影、多人同時控制、網頁管理平台 |

正式版目標（非 MVP）：操作已提升權限的程式（如管理員 PowerShell），前提是 G0-06 找到符合 Windows 安全模型、不降低安全設定的做法。

效能目標為待量測值，不是保證：區網輸入到畫面延遲 < 50 ms、頻寬 2–8 Mbps、被控端 CPU < 15%（有硬體編碼時）。

## 三、系統架構

只有兩個程式：被控端 Host.exe 在使用者登入後自動執行、等待連線，控制端主動連過去；畫面、鍵鼠與剪貼簿、檔案分走同一個埠上的三條加密 TCP 連線。

被控端由兩個使用者權限程式組成：Host.exe 負責網路、登入、畫面、剪貼簿、檔案，並接收、驗證遠端鍵鼠事件；HostGuard.exe 負責把已授權的鍵鼠事件送進系統（SendInput）、追蹤按鍵狀態，並監看 Host.exe。安裝時（一次性需要系統管理員）放在 Program Files、建立入站防火牆規則與「登入時執行」的排程工作；之後每次登入，排程工作以該使用者權限啟動 HostGuard，再由 HostGuard 啟動 Host.exe。HostGuard 不連網、不讀剪貼簿、不處理畫面或檔案，沒有 SYSTEM 權限。

### 為什麼不需要 Windows 服務

| Windows 服務能提供的 | V2.2 的需求或替代做法 | 需要服務？ |
| --- | --- | --- |
| 登入前、登出後仍執行 | 不需要（決議 3） | 否 |
| 以 LOCAL\_SYSTEM 擷取與操作 UAC、登入、鎖定畫面 | 不需要（決議 2、3） | 否 |
| Ctrl+Alt+Del（SendSAS） | 不需要 | 否 |
| 監聽網路埠 | 一般程式即可監聽 52100；入站防火牆規則由安裝程式一次建立 | 否 |
| 自動啟動、崩潰重啟 | 排程工作於登入時啟動 HostGuard，由 HostGuard 重啟 Host.exe | 否 |
| 多位使用者共用一個監聽者 | 只有主控台上作用中的工作階段監聽；切換使用者時讓出埠 | 否 |
| 以 SYSTEM 進程越過 UIPI 操作管理員視窗 | 需求要求不提升權限、不降低安全，改以 UIAccess 候選（G0-06）評估 | 否 |

結論：MVP 沒有必須由服務提供的功能，採用使用者模式 Host.exe。代價是 Host.exe 與使用者同權限，同一使用者下的惡意程式能碰到它的設定；但這類程式本來就能操作該使用者的桌面，風險並未增加。日後若要支援登入前連線或 UAC，才需重新引入服務。

### Host.exe 內部模組

- 網路：TLS 監聽、帳密驗證、三條連線、Session Token。
- 擷取與編碼；接收並驗證遠端鍵鼠事件（授權狀態、世代編號），經本機 IPC 交給 HostGuard；Host.exe 本身不呼叫 SendInput。
- 剪貼簿；檔案傳輸（限速、暫存、驗證）。
- 工作階段監控；系統列圖示（帳號設定、指紋、被操控提示、中斷）。
- UIAccessInputBroker：候選設計，G0-06 通過且決定採用才加入；因注入已移至 HostGuard，届時一併評估由哪個元件承擔。

連線流程：

1. 使用者在控制端輸入被控端 IP（或網域名稱）、帳號、密碼。
2. 建立 Control 連線並完成 TLS 1.3 握手；首次連線須在被控端螢幕核對 SHA-256(SPKI) 指紋。
3. Host.exe 驗證帳密，發出一次性 Session Token。
4. 控制端以 Token 開 Video 與 File 連線。Control 中斷時撤銷整個工作階段；Video 或 File 中斷時只重連該條（見第七節）。

### 工作階段狀態

Host.exe 以 WTSRegisterSessionNotification 接收自己所在工作階段的事件（事件時序待 G0-03 驗證）。

桌面可控制的判定：以下三項同時成立才算「可控制」，任一項不成立即進入暫停。

- 工作階段未鎖定，且在主控台上。
- 目前的輸入桌面是一般桌面（OpenInputDesktop 可開啟且為 Default）。
- DXGI 擷取正常產生畫面。

暫停時（G0-03 必要）：

1. 立即停止注入鍵鼠，釋放所有遠端按下的鍵。
2. 輸入世代編號加 1；之後收到的舊世代鍵鼠事件一律丟棄。
3. 停止傳送畫面與剪貼簿同步。
4. 控制端把最後一張畫面變暗並蓋上「已暫停，非即時畫面」，不當作即時畫面顯示。

恢復時（G0-03 必要）：

1. 三項判定連續成立 1 秒以上（初始值）才開始恢復。
2. 先送出新的 IDR 關鍵幀；控制端顯示新畫面後回覆新世代編號，並清空自己尚未送出的輸入。
3. Host.exe 收到回覆後才接受新世代的鍵鼠事件、恢復剪貼簿同步。

| Windows 狀態 | 行為 | 控制端訊息 |
| --- | --- | --- |
| 已登入、一般桌面 | 可遠端控制 | 無 |
| 鎖定（收到鎖定事件） | 暫停，連線保持 | 「遠端已鎖定，等待本機解鎖」 |
| 本機解鎖 | 依恢復程序自動恢復 | 無 |
| 未鎖定但桌面不可控制（可能是 UAC 或其他原因） | 暫停，連線保持 | 通用：「遠端桌面暫時無法操作」；G0-07 能可靠辨識 UAC 時，才改顯示「遠端出現系統管理員提示，需本機處理」 |
| 使用者登出、關機 | 通知控制端後中止連線 | 「遠端使用者已登出」 |
| 切換使用者 | 中止連線、撤銷授權並讓出 52100 埠；另一使用者的 Host 不繼承任何授權 | 「遠端已切換使用者」 |

### HostGuard 規格

HostGuard 是唯一執行 SendInput 的程式；注入與按鍵狀態在同一個執行緒內更新，Host.exe 崩潰不會讓狀態失準。

本機 IPC：

- HostGuard 建立 Named Pipe，ACL 只允許目前使用者；並檢查連線端的工作階段 ID 相同、程序 ID 是自己啟動的 Host.exe（GetNamedPipeClientProcessId）。
- 訊息白名單：鍵鼠事件（含世代編號）、輸入心跳、暫停、恢復（新世代）、全部釋放。其他訊息丟棄並記錄。
- 不提供執行命令、讀檔、剪貼簿等任何其他功能。

注入與狀態：

1. 收到鍵鼠事件先檢查世代編號與「桌面可控制」狀態，不符就丟棄。
2. 呼叫 SendInput；回傳成功後才把按下的鍵或滑鼠按鈕加入狀態表，放開成功後移除。
3. 只釋放自己按下且仍在狀態表中的鍵與按鈕，不碰本機使用者按的其他鍵。

不可控制時不注入：HostGuard 自己也登記工作階段事件，並在注入前確認輸入桌面為一般桌面。鎖定、登出、切換使用者、UAC 安全桌面或 Host.exe 已通知暫停時，丟棄所有事件並釋放狀態表中的鍵。

監看與復原：

- HostGuard 持有 Host.exe 的程序 handle 並等待其結束。
- Host.exe 無回應：有按鍵按住時超過 1 秒沒收到輸入心跳，先釋放狀態表中的鍵。
- Host.exe 結束：立即丟棄佇列中的事件、釋放狀態表中的鍵與按鈕，再依重啟政策處理。

| 結束類型 | 判定 | 處理 |
| --- | --- | --- |
| 正常結束 | 結束碼 0（系統列「結束」、登出、關機） | 不重啟；HostGuard 一併結束 |
| 異常崩潰 | 非 0 結束碼或例外結束 | 退避重啟（1、2、4、8、16 秒）；10 分鐘內第 6 次不再重啟，寫入事件記錄 |

重啟後的 Host.exe 不沿用任何舊授權，控制端須重新登入。

故障限制（不保證立即釋放）：

| 情況 | 結果 |
| --- | --- |
| HostGuard 本身崩潰或被結束 | 狀態表遺失，按住的鍵可能殘留到本機按下該鍵或重新登入；Host.exe 偵測 IPC 中斷後立即停止遠端控制並提示，排程工作依失敗重啟設定重新啟動 HostGuard（間隔待驗證） |
| 系統停止回應，或 HostGuard 執行緒被嚴重延遲 | 釋放可能晚於 3 秒 |
| 本機使用者剛好也按著同一個鍵 | 釋放遠端按鍵時，該鍵也會被視為放開（Windows 無法區分同一鍵的兩個來源） |
| 注入被 UIPI 擋下 | SendInput 不會說明是 UIPI 所致，狀態表可能與實際不符；釋放時可能送出多餘的放開事件（行為待 G0-06 確認） |

驗收承諾：Host.exe 崩潰或無回應後 3 秒內放開遠端按住的鍵與按鈕（GUARD-01）；上表情況除外，且需保留測試證據。

## 四、技術選型

全部用 C# / .NET 10（LTS）：只支援 Windows，而 .NET 呼叫 Windows API、COM、OLE 拖放最省力，兩個程式也能共用同一份協定程式碼。

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 控制端 UI | WPF，畫面區用 HwndHost 嵌 D3D11 SwapChain；畫面區的鍵鼠與拖放由該 Win32 視窗自己處理（WndProc + RegisterDragDrop） | HwndHost 內 WPF 收不到滑鼠、鍵盤與拖放事件；G0-04 實測，不通過就比較 D3DImage 或獨立視窗 |
| 被控端 | Host.exe（無主視窗、有系統列圖示）+ HostGuard.exe（輸入注入、按鍵狀態、監看與重啟），排程工作在登入時以使用者權限啟動 | 需求不含登入前與安全桌面；權限最低、架構最簡單 |
| 管理員視窗 | 候選：UIAccessInputBroker（uiAccess=true、受信任簽章、安裝於 Program Files）；G0-06 評估，並比較其他符合安全模型的做法 | 不阻擋 MVP；不提升權限、不降低安全設定 |
| 設定與金鑰 | 存在使用者的 %LOCALAPPDATA%，DPAPI（目前使用者）加密；密碼以 Argon2id 雜湊 | Host.exe 以使用者權限即可讀寫，不需管理員 |
| 螢幕擷取 | DXGI Desktop Duplication API（Vortice.Windows 封裝） | 只回傳有變化的畫面，資料留在 GPU |
| 影像編碼 | H.264：啟動時探測 Media Foundation 硬體編碼，失敗改用軟體編碼並降畫質或 fps | 不是每台電腦都有可用的硬體編碼；若用 OpenH264，其發佈、授權與專利責任需另行確認 |
| 解碼與顯示 | Media Foundation 解碼 → D3D11 繪製 | Windows 11 內建 |
| 傳輸 | TCP + TLS 1.3，同一個埠 52100 上開三條連線：控制、畫面、檔案；檔案連線限速 | 避免大檔案影響鍵鼠 |
| 訊息格式 | MessagePack，每種訊息固定 schema | 拒絕未知、超長、格式錯誤的資料 |
| 安裝包 | WiX MSI（安裝時需管理員一次）：安裝到 Program Files、防火牆規則（預設只允許私有網路）、登入時執行的排程工作、程式碼簽章；升級保留主機金鑰與帳號設定 | 執行檔放在一般使用者不可寫的路徑；升級不可意外重置信任 |

替代選項：若熟悉 Rust，可以 RustDesk 為藍本，但 Windows COM / OLE 部分會比 C# 費工。

## 五、各功能實作方式

畫面、鍵鼠、剪貼簿都有成熟做法；Spike 0 的重點是 HwndHost 拖放、資料夾雙向傳輸與完整性，以及工作階段事件。

### 1. 遠端畫面

- AcquireNextFrame 只在畫面有變化時編碼；游標形狀與位置另外傳，由控制端自己畫。
- 畫面落後時清空待送佇列、要求編碼器產生 IDR 關鍵幀，解碼端從 IDR 重新開始，不單獨丟 P 幀。
- 必測 DXGI\_ERROR\_ACCESS\_LOST、解析度變更、HDR、旋轉、跨 GPU 多螢幕、睡眠恢復；發生時重建擷取。
- 部分應用程式會刻意排除螢幕擷取，不承諾所有視窗內容都看得到。
- 鎖定或 UAC 提示時出現的是安全桌面，使用者權限擷取不到；依工作階段狀態表暫停並提示。

### 2. 鍵盤與滑鼠

- HostGuard 用 SendInput 注入（Host.exe 只驗證後轉交）：鍵盤用 KEYEVENTF\_SCANCODE；滑鼠用 ABSOLUTE + VIRTUALDESK，座標正規化到 0–65535；程式宣告 Per-Monitor V2 DPI。
- 管理員視窗：一般權限送出的輸入會被 UIPI 擋下，而且 SendInput 不會回報是 UIPI 擋下。Host.exe 檢查前景視窗所屬程序的完整性層級，較高時提示「此視窗以系統管理員執行，目前無法遠端操作」（偵測方式待驗證）。解法見 G0-06。
- WH\_KEYBOARD\_LL 只在畫面區有焦點、且使用者開啟「轉送系統快捷鍵」時啟用；不保證所有組合鍵都攔截得到。
- 中文：預設送掃描碼、使用遠端輸入法；另有「貼上 Unicode 文字」模式用 KEYEVENTF\_UNICODE。需驗證注音、拼音、英文、不同鍵盤配置、增補字元與終端機。
- 按鍵釋放由被控端負責：
  - HostGuard 在 SendInput 成功後記錄所有由遠端按下、尚未放開的按鍵與滑鼠鍵。
  - 控制端有按鍵按住時每 250 ms 送一次輸入心跳；被控端超過 1 秒沒收到就全部釋放（初始值，Spike 後調整）。
  - Control 或 Video 中斷、桌面進入暫停（鎖定、UAC 或擷取中斷）、切換使用者時立即全部釋放；恢復時以輸入世代編號丟棄暫停前未處理的鍵鼠事件。
  - Host.exe 崩潰時由 HostGuard 依按鍵狀態表釋放（見第三節）。

### 3. 文字複製貼上

- 只在已登入的連線中啟用；工具列有開關，並提示「遠端可讀取你的剪貼簿」。
- 兩端用 AddClipboardFormatListener 監聽，只同步 CF\_UNICODETEXT，單次上限 1 MB。
- 防迴圈：每次同步帶來源 Session ID 與事件序號，並標記「自己剛寫入」，不只靠雜湊。
- 斷線或桌面暫停時停止同步，恢復程序完成後才重新同步。

### 4. 檔案拖拉（檔案與資料夾，兩個方向）

| 方向 | 做法 |
| --- | --- |
| 本地 Explorer → 遠端 | 把本地檔案或資料夾拖進遠端畫面區或傳輸面板；控制端以原生 IDropTarget 取得清單（CF\_HDROP）、遞迴列出資料夾，傳到遠端「下載」或面板中選定的資料夾，保留資料夾結構 |
| 遠端檔案面板 → 本地 Explorer | 主方案：虛擬檔案拖放（CFSTR\_FILEDESCRIPTORW 列出檔案與資料夾、CFSTR\_FILECONTENTS 以 IStream 串流）。備援：先下載到本地已驗證暫存區，再以一般檔案拖放（CF\_HDROP） |

遠端 Explorer 直接拖到本地 Explorer 已移除，不研究也不開發。只做複製，不刪除來源。

遠端 → 本地的完整性：

- 串流主方案：每個 256 KB 資料塊驗證區塊雜湊；每個檔案的最後一塊扣住，直到全檔 SHA-256 通過才交給 Explorer。驗證失敗或中斷時 IStream 回傳錯誤。Explorer 收到錯誤後是否刪除目標的殘缺檔，G0-05 必須實測；若不會，改以暫存方案為預設。
- 暫存備援：在面板選取後先下載到 %LOCALAPPDATA% 下的暫存區（.part → 驗證 → 改名），標示「已就緒」後才能拖出，Explorer 複製的是本機已驗證的檔案。暫存區有容量上限，拖出後或 24 小時後清除。
- IDataObjectAsyncCapability 為可選介面，可與目的地協商背景傳輸，但不保證被採用；讀取設逾時，慢速網路不可讓 Explorer 或工具 UI 無限期卡住。
- 目標拒絕、取消或只複製部分檔案時回報狀態。

### 5. 檔案傳輸頻寬限制

- File 連線以 token bucket 限速；預設上限為最近量測可用頻寬的 70%，使用者可在工具列調整。
- 監看 Control 連線來回延遲與 Video 送出佇列：延遲比基準高 50 ms 以上，或畫面佇列堆積時，檔案速率減半；恢復後逐步加回。
- 以上數值為初始值，以 PERF-01（傳 1 GB 時鍵鼠 p95 延遲）調整。

### 6. 檔案安全與一致性

- Host.exe 以使用者權限讀寫，不會越過使用者的 ACL。
- 拒絕 `..`、絕對路徑、非法檔名、替代資料流、符號連結與 junction；路徑解析後再檢查 reparse point，並以開檔後的 handle 確認最終路徑（GetFinalPathNameByHandle），防止 TOCTOU。
- 先寫入 `.part` 暫存檔，SHA-256 串流計算通過後再改名；處理取消、中斷、磁碟滿、同名、檔案被占用、唯讀目標。
- 資料夾深度與檔案數設上限；進度顯示總位元組與檔案數。

## 六、帳號認證與安全

帳號密碼存在被控端、由 Host.exe 驗證；全程 TLS 1.3，首次連線必須人工核對主機指紋，否則第一次連線就可能被冒充。

### 帳號密碼

- 被控端可建立一或多組帳號，密碼至少 10 字元，以 Argon2id 雜湊存放；設定檔存於使用者的 %LOCALAPPDATA%，以 DPAPI（目前使用者）加密。
- 以 Windows 帳密登入（LogonUser）列為研究項；MVP 只支援自訂帳密。
- 控制端預設不記住密碼；若勾選記住，用 DPAPI（目前使用者）加密並提供清除功能。
- 登入失敗只記來源 IP 與時間，不記錄輸入的帳號與密碼；任何記錄都不寫密碼、Token 或剪貼簿內容，檔案路徑稽核記錄限管理員讀取。

### 主機身分（防冒充與竊聽）

1. 被控端第一次啟動產生 ECDSA P-256 金鑰對與自簽憑證，私鑰以 DPAPI 保存。
2. 主機指紋一律為 SHA-256(SubjectPublicKeyInfo)，以 16 進位分組顯示；被控端系統列顯示的、控制端顯示與記住的，都是這個值，不使用憑證本身的指紋。
3. 控制端首次連線顯示指紋，使用者必須在被控端螢幕或其他可信管道核對後才能繼續，未確認不可登入。
4. 記住的是主機公鑰（裝置身分），不是 IP。憑證以同一把金鑰重新簽發時指紋不變；金鑰變了就拒絕，需人工重新核准。

### 防暴力破解與工作階段控制

- 每個來源漸進延遲（1、2、4…秒，上限 60 秒）+ 全域節流 + 同時連線上限；不採「鎖 15 分鐘」，避免被惡意鎖死無法登入。
- 預設同一時間只允許一名控制者；斷線即撤銷畫面、鍵鼠、剪貼簿、檔案的授權。
- 被控端浮動列顯示連線狀態與「中斷」；可關閉無人值守，改成每次連線需本機按「允許」。
- 稽核記錄寫入 Windows 事件記錄：連線時間、來源 IP、帳號、傳輸了哪些檔案。
- 執行檔放在一般使用者不可寫的路徑（Program Files），避免被替換。

### 網路邊界

- 同區網：被控端防火牆放行 TCP 52100 即可直連。
- 跨網段或網際網路：被控端需有可到達的 IP 並設定通訊埠轉發；遇到 CGNAT 或兩端都在受限 NAT 後面，沒有中繼就無法保證連得上。控制端要明確提示「連不到該位址」，不誤報成密碼錯誤。
- 完全不用第三方服務：用自管 WireGuard 或路由器內建 VPN。
- Tailscale、ZeroTier 較省事，但依賴它們的協調服務，Tailscale 某些情況還會走它的 DERP 中繼，不符合「完全不經第三方」。
- 防火牆規則預設只允許私有網路或指定來源位址，不對全網開放 52100。

## 七、通訊協定設計

同一個埠 52100 上開三條 TLS 連線，各有角色：大檔案只會塞住檔案那條，不會拖慢鍵鼠。

| 連線 | 內容 | 建立方式 |
| --- | --- | --- |
| Control | 版本握手、能力交換、登入、鍵鼠、文字剪貼簿、心跳、螢幕清單、品質調整 | 第一條；登入成功後取得短效 Session Token |
| Video | H.264 資料（大幀分塊傳送）、游標形狀與位置 | 出示 Session Token 綁定同一工作階段 |
| File | 檔案清單、256 KB 資料塊與雜湊、確認、取消；限速傳送 | 同上 |

- 新連線必須在同一主機 TLS 身分下出示有效 Session Token 才能取得 Video 或 File 角色，匿名連線不能自選角色。
- 封包表頭：`[Length][MessageType][RequestId][Sequence]` + MessagePack 內容；握手帶 ProtocolVersion 與 Capabilities，版本不相容就明確提示更新。
- 每種訊息有固定 schema、長度上限與錯誤狀態；未知類型、超長或格式錯誤即斷線。檔案清單項數與資料夾深度也有上限。
- 每條連線用有上限的送出佇列與背壓；畫面佇列塞住時要求 IDR，不無限累積。
- 心跳每 2 秒一次，6 秒無回應即斷線；Control 斷線時另兩條一併關閉，授權全部撤銷，被控端釋放所有按鍵。

### 連線中斷處理

| 中斷的連線 | 處理 |
| --- | --- |
| Control | 撤銷整個工作階段：關閉 Video、File，Token 全部失效，被控端釋放按鍵；控制端須重新登入 |
| Video | 被控端釋放按鍵並遞增輸入世代，控制端顯示「畫面重新連線中」且不送鍵鼠；在 Control 上申請新的 Video Token 重連，成功後從 IDR 開始並依恢復程序接受輸入；Control 保持 |
| File | 進行中的傳輸暫停；申請新的 File Token 重連，從最後一個已驗證的資料塊續傳；Control、Video 不受影響 |

重連以指數退避嘗試（1、2、4…秒），30 秒內未成功就顯示失敗並可手動重試；只要 Control 仍在，就不關閉遠端桌面。

### Session Token 規格

| 屬性 | 規格 |
| --- | --- |
| 產生 | CSPRNG 產生 256 位元隨機值 |
| 生命週期 | 發出後 30 秒內須用於開子連線，且不會活得比 Control 連線久 |
| 角色 | Video、File 各發一枚，不可跨角色使用 |
| 使用次數 | 一次性，用過即失效；子連線重連需在 Control 上重新申請 |
| 綁定 | 帳號、Windows Session ID、Control 連線 ID、角色 |
| 撤銷 | Control 斷線、本機按中斷、重新登入時全部失效 |
| 保存 | 只在記憶體，不寫入記錄或設定檔 |
| 防重放 | 重複使用、過期、跨角色一律拒絕，並記錄來源 IP |

子連線不直接送出 Token：被控端先送一次性 nonce，控制端回 HMAC-SHA256(Token, nonce + 角色)。若 .NET 能取得 TLS exporter（RFC 9266），再把子連線授權綁定到該條 TLS 交握，於 Spike 0 確認。

## 八、開發階段與時程

估算 12–17 週（含 Spike 0，非承諾），假設一名熟悉 C# 的全職開發者；不熟 Windows COM 與 Media Foundation 時取上限或更長。已扣除 Windows 服務、本機 IPC、安全桌面與遠端 Explorer 拖出研究的工時。Spike 0 已於 2026-11-09 核准開始；M1 起待 Spike 0 通過後核准。

| 階段 | 交付 | 通過條件 |
| --- | --- | --- |
| Spike 0（2–3 週） | G0-01～05 的最小原型；G0-06、07 各限 3 天研究 | G0-01～05 全部實機通過（含 G0-03 的安全暫停與恢復） |
| M1（3–4 週） | Host.exe 與登入時自動執行、TLS 與登入、三條連線、畫面與鍵鼠、工作階段狀態、按鍵釋放、單人連線 | 兩台 Win11 連續使用 2 小時；SESS-01、SESS-02 通過 |
| M2（2–3 週） | 文字剪貼簿、中文輸入與 Unicode 貼上、Win 鍵轉送、多螢幕、畫質調整、管理員視窗提示 | HID-01、CLP-01、VID-01、VID-02 通過 |
| M3（3–4 週） | 傳輸引擎：檔案與資料夾雙向、限速、.part 與 SHA-256、暫存區、本地拖入、面板拖出、進度與取消 | FILE-01～03、PERF-01 通過 |

### Spike 0 通過條件

不以「原型有執行」算通過；每項都在兩台實體 Windows 11 上實測。結果只能標 PASS、FAIL 或未測：PASS 須附測試步驟、測試機型號與 Windows 版本、記錄檔及螢幕錄影；FAIL 保留失敗證據與重現步驟。未經實測的項目不得標為 PASS。

| Gate | 必須驗證 | 等級 | 失敗處理 |
| --- | --- | --- | --- |
| G0-01 | 兩台 Win11 直接 IP、TLS 1.3、SHA-256(SPKI) 指紋核對、自訂帳密登入、三條連線與一次性 Token；Video、File 中斷後可獨立重連，Control 中斷則撤銷工作階段 | 必要 | 阻擋 M1 |
| G0-02 | DXGI → H.264 → 控制端顯示、鍵鼠可操作 | 必要 | 阻擋 M1 |
| G0-03 | ① Host.exe 於登入時以使用者權限自動啟動。② 安全暫停與恢復：鎖定、UAC 或擷取中斷時停止輸入、畫面與剪貼簿，不把舊畫面當即時畫面，桌面恢復正常後才重新接受控制，且丟棄暫停前未處理的鍵鼠。③ 登出時中止連線。④ Windows 使用者 A → B → A：舊 Host 讓出 52100，新 Host 不繼承任何授權。⑤ 斷線、Video 中斷、輸入逾時時釋放按鍵；HostGuard 的 GUARD-01～05 實機通過 | 必要 | 阻擋 M1 |
| G0-04 | HwndHost 畫面區收得到鍵鼠，且能從本地 Explorer 拖入檔案與資料夾 | 必要 | 改用 D3DImage 或獨立視窗，以延遲與事件可靠度實測定案 |
| G0-05 | 遠端面板的檔案與資料夾能拖到本地 Explorer；雜湊不符或中斷時目標不留殘缺檔；暫存備援可運作 | 必要 | 串流不符完整性 → 以暫存方案為預設；兩者皆不通過 → 阻擋 M3 |
| G0-06 | 找出符合 Windows 安全模型的方式操作管理員 PowerShell（候選：UIAccess），不提升權限、不降低安全設定 | 不阻擋 | MVP 維持「偵測並提示」；正式版另行規劃 |
| G0-07 | 嘗試辨識 UAC 提示並顯示專用訊息；無法可靠辨識時使用通用訊息，不得把所有 DXGI 擷取失敗判為 UAC | 不阻擋 | 一律顯示「遠端桌面暫時無法操作」 |

同時確認：.NET 能否取得 TLS exporter（Session Token 綁定用），以及軟體 H.264 編碼器的授權與專利責任。

## 九、風險與注意事項

架構簡化後，技術風險集中在 HwndHost 拖放、拖出完整性與工作階段事件；交付風險仍是防毒誤判與外網連不到。

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 工作階段事件時序不如預期或遺漏 | 鎖定後仍送輸入，或解鎖後未恢復 | G0-03 實測；以擷取狀態與輸入桌面交叉確認 |
| WPF HwndHost 收不到拖放或鍵鼠 | 無法把檔案拖進遠端畫面 | G0-04 先驗證；不通過就改 D3DImage 或獨立視窗 |
| 虛擬檔案串流無法保證完整性 | 本地目標留下殘缺檔 | G0-05 實測；不符就以暫存方案為預設 |
| 管理員視窗無法操作 | 部分管理工作需本機處理 | MVP 偵測並提示；G0-06 評估 UIAccess 候選 |
| Host.exe 與使用者同權限 | 同一使用者下的惡意程式可碰到設定 | 接受（同權限程式本來就能操作桌面）；DPAPI 加密、執行檔放 Program Files |
| 防毒 / SmartScreen 誤判 | 安裝或執行被擋 | 程式碼簽章、每版都簽、向 Microsoft 回報誤判 |
| CGNAT 或受限 NAT | 用 IP 連不到 | 自管 WireGuard 或路由器 VPN；控制端明確提示「位址不可達」 |
| 對方 IP 會變 | 連線位址失效 | DDNS 或 VPN 固定 IP；主機以公鑰識別，不影響信任 |
| 通訊埠暴露在網際網路 | 被暴力破解 | 強密碼、漸進延遲、防火牆限私有網路或指定來源 |
| 法律 | 未經同意操控他人電腦違法 | 只用於自己或已授權的電腦，保留「正在被操控」提示 |

## 十、最小驗收案例

以下 24 項全部通過才算 MVP 完成。

| ID | 驗證項目 | 通過標準 |
| --- | --- | --- |
| NET-01 | 同區網 IP 連線 | 不需外部服務；關閉外網仍可連線 |
| NET-02 | 無法路由的 IP / CGNAT | 明確提示不可達，不誤報為驗證失敗 |
| SEC-01 | 首次指紋核對 | 兩端顯示相同的 SHA-256(SPKI)，可由被控端獨立核對，未確認不可繼續 |
| SEC-02 | 主機憑證變更 | 直接拒絕，需人工重新核准 |
| SEC-03 | 錯誤密碼、爆破、超大封包、Token 重放 | 節流、拒絕、可稽核、不當機 |
| SESS-01 | 登入、斷線、本地中斷、Host.exe 崩潰 | 授權即時撤銷、按鍵釋放；Host.exe 崩潰時依 GUARD-01 |
| SESS-02 | 鎖定、本機解鎖、登出、Windows 使用者 A → B → A 切換 | 行為符合工作階段狀態表，不誤連其他使用者桌面；舊 Host 讓出 52100，新 Host 不繼承授權 |
| VID-01 | 1080p 畫面與游標 | 無嚴重黑屏、無長期積壓與不同步 |
| VID-02 | UAC 提示、Win+L、解析度切換 | 暫停期間不送輸入與剪貼簿、不把舊畫面當即時畫面；恢復後丟棄舊輸入；無法可靠辨識 UAC 時顯示通用訊息 |
| HID-01 | 注音、英文、Alt+Tab、高 DPI | 正確輸入與定位 |
| HID-02 | 前景為管理員 PowerShell | MVP：明確提示無法操作；採用候選方案後：可打字與點擊 |
| CLP-01 | 雙向中英文剪貼簿 | 不迴圈、不重複、斷線停止同步 |
| FILE-01 | 1 GB 大檔雙向 | 雜湊一致，取消與錯誤有明確結果 |
| FILE-02 | 千個小檔與巢狀資料夾雙向 | 路徑與結構保留、無路徑穿越、同名行為符合預期 |
| FILE-03 | 本地 Explorer 拖入、遠端面板拖出（檔案與資料夾） | 目標真的建立正確的檔案與資料夾結構 |
| FILE-04 | 拖出過程中斷線或雜湊不符 | 本地目標不留殘缺檔，並顯示失敗原因 |
| PERF-01 | 傳 1 GB 檔時操作鍵鼠 | 區網、指定測試機下，鍵鼠 p95 輸入到畫面延遲 < 100 ms（暫定門檻） |
| INST-01 | 安裝、升級、移除 | 排程工作與防火牆正確；升級保留主機金鑰與帳號；移除時詢問是否刪除使用者資料 |
| NET-03 | 分別中斷 Video、File、Control 連線 | Video、File 獨立重連且遠端桌面不關閉，File 從已驗證資料塊續傳；Control 中斷則撤銷整個工作階段 |
| GUARD-01 | Host.exe 崩潰前後的按鍵狀態：遠端按住 Shift、Ctrl 與滑鼠左鍵時，分別以強制結束、未處理例外、Host 無回應三種方式中斷 | 記錄崩潰前後各鍵狀態與時間戳；3 秒內全部放開；重啟後須重新登入；三種方式各附記錄檔與錄影 |
| GUARD-02 | 不影響本機使用者 | 遠端控制中、Host 崩潰與恢復期間，本機實體鍵鼠皆可正常操作；HostGuard 只放開狀態表中的鍵，本機按住的其他鍵不被放開；經 IPC 增加的輸入延遲 p95 < 5 ms（暫定） |
| GUARD-03 | 重啟政策 | 正常結束（系統列結束、登出）不重啟；異常結束依退避重啟；10 分鐘內第 6 次不再重啟並寫入事件記錄 |
| GUARD-04 | 本機 IPC 安全 | 非 HostGuard 啟動的程序、其他使用者或其他工作階段連線被拒；白名單外訊息與舊世代事件被丟棄並記錄 |
| GUARD-05 | 不可控制狀態與 HostGuard 故障 | 鎖定、UAC、登出、切換使用者時，即使收到事件也不注入並記錄丟棄；結束 HostGuard 時，Host.exe 立即停止遠端控制並提示，並記錄是否有殘留按鍵（已知限制） |

測試設備待定，建議至少一台內顯筆電與一台獨顯桌機，並在驗收報告寫明型號、Windows 版本與網路條件。延遲一律以 p95 評估。
